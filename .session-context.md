## Текущее состояние

Документация приведена в соответствие после ревью v1.1. Основные изменения v1.2 (полный список — `docs/requirements/index.md`):

- `ModelDocument` → `SourceModel` → `ModelSlice`; `imports` на уровне документа.
- `UNSET` vs `default: null`; полная null-матрица из 12 комбинаций.
- `extends` — короткая форма и `{import, entity}`; только внутри import-closure.
- `sources[].input` фильтрует свой source; срез генератора = `generators[].input` + closure по enums/types.
- Обязательные `format`/`version`; один запуск — один формат.
- `ruamel.yaml` (YAML 1.2), duplicate keys → error.
- Ownership + per-generator manifest `output_dir/.mg/manifests/<id>.json`.
- `cleanup: off` по умолчанию; удаляются только неизменённые owned-файлы.
- Lock `.mg/lock`; `--plan`, `--check`, `--force`, `--yes`, `--include-disabled`, `--allow-outside-imports`.
- `--format` → `--output-format`; exit code 130 при Ctrl+C.
- Публичный API: `Engine`, `EngineReport`, `Diagnostic`, `ModelSlice`, `FieldDef`, `EnumDef`.
- `Field`/`Enum` переименованы в `FieldDef`/`EnumDef`.

## Принятые решения (актуальные)

### Модель данных
- Явные этапы: `ModelDocument` (header + imports + model) → `SourceModel` (после композиции) → `ModelSlice` (замкнутый срез для генератора).
- `metadata` доступен у entity/field/enum/type/source; format-плагин складывает свои поля под namespace формата.
- `default`: отсутствие ключа = `UNSET`, `null` — явное значение. `required=false, nullable=false, UNSET` — валидное состояние.
- Null-матрица (ТЗ §3.6): 12 комбинаций; MG010 — только `nullable=false` + `default=null`; MG011 (warning) — `required=true` + `nullable=true`.
- `constraints` — у поля и CustomType; слияние по атрибутам; неприменимые/противоречивые — MG021.
- `CustomType.base` разрешается транзитивно, цикл/глубина > 10 — MG020.
- `updated_at`/`version` — на уровне entity; устаревшая дата — MG014 (warning, opt-in).
- `required_by_default` удалён.

### Форматы
- `format` и `version` обязательны. Неизвестный формат — MG007, версия — MG008, без «тихого» default.
- Один запуск — один формат (MG007). Импортируемый документ обязан иметь тот же формат.
- `entity-model` зарезервирован; format-плагин расширяет через `EntityModelFormat` (parser + hooks).
- `primitive_types` объявляются форматом.

### Композиция / merge
- ADR-0001: merge только по явным связям (`imports`/`entity.extends`), аддитивный, детерминированный; конфликты имён — MG002.
- Entity extends: короткое имя или `{import, entity}`; цепочки разрешены; цикл/глубина > 10 — MG009; наследуются только `fields`.
- Импорты только внутри project root (MG022), кроме `--allow-outside-imports`; циклы/глубина > 10 — MG006.
- Один resolved-путь обрабатывается один раз; дубли в `sources` — MG024 (warning).
- Discovery каталогов: `**/*.yaml|yml`, лексикографический порядок, пропуск `.git/.mg/output_dir/...`; non-model YAML — MG023.

### Срезы и конфиг
- `sources[].input` и `generators[].input` — вложенные объекты (`entities/enums/types`), пусто = все.
- Финальный срез = `generators[].input` по union отфильтрованных sources + closure по enums/types; неизвестное имя — MG018.
- Все пути `.mg.yaml` — от каталога конфига; `-o` заменяет корень.
- `variables` → `context.variables`; CLI > config.

### Плагины
- Два типа: `GeneratorPlugin` (entry points `metadata_generator.generators`) и `FormatPlugin` (`...formats`).
- `api_version` — `ClassVar[Literal["1"]]`; несовместимый не ломает запуск, если не выбран; выбранный → exit 2.
- Вход генератора — `ModelSlice` + `GenerationContext` + `GeneratorConfig`; AppConfig не передаётся.
- Выход — `Artifact(path: относительный POSIX, content: str)`; ошибки → артефакты генератора отбрасываются.
- `Diagnostic` — структурированный (level, code, message, location) вместо строк.
- Локальные плагины — только editable install; `sys.path`/`plugins_dir` не поддерживаются.

### Запись артефактов
- Ownership: только файлы из манифеста генератора можно перезаписывать/удалять; чужие — MG041, перезапись через `--force`.
- Per-generator манифест: `output_dir/.mg/manifests/<generator-id>.json`, пишется атомарно после успешной записи генератора.
- `on_conflict: overwrite (default) | skip | error`; два генератора на один путь — MG042.
- Валидация путей: относительный POSIX, без `..`, NUL, backslash, reserved names, длин; NFC; symlink за пределы `output_dir` — MG040; case-collision — MG042.
- Atomic write: staging внутри `output_dir` → `os.replace`; lock `.mg/lock`; partial batch допускается, manifest последний.
- Cleanup: `off` (default) | `prompt` (только tty) | `enabled`; удаляются только unchanged owned-файлы; изменённый — MG050 (warning).
- `--plan`/`--dry-run`/`--check` не создают каталоги и не берут write-lock.

### CLI
- Команды: `generate`, `watch`, `init`, `clean`; sub-apps `config show|validate`, `model validate|schema`, `gen list|info`, `format list`.
- Флаги: `-g`, `-c`, `-o`, `--var`, `--dry-run`, `--plan`, `--check`, `--clean`, `--strict`, `--force`, `--yes`, `--include-disabled`, `--allow-outside-imports`, `--output-format text|json`.
- Exit codes: 0 успех / 1 errors, drift `--check` или strict warnings / 2 config-usage / 130 Ctrl+C.
- При падении одного генератора остальные продолжаются.

### Прочее
- Единая точка логирования: `config/logging.py`; без `basicConfig(force=True)`; библиотека не настраивает root-logger.
- CLI-вывод (rich) в stdout, логи в stderr/file — JSON-отчёт не ломается.
- `Engine` — библиотечный фасад: `build()` без записи, `generate()` с записью; не вызывает `sys.exit`.
- `ruamel.yaml` + YAML 1.2; `py.typed`; Python 3.11+; `watchdog` — optional extra `[watch]`.
- Golden-file тесты через reference-плагин из `examples/`.
