# ADR-0002: Type checker — Pyrefly вместо mypy

- **Статус:** принято
- **Дата:** 2026-11-11
- **Связанные документы:** [ТЗ v1.2 §12.3](../requirements/v1.2.md), [System Design §12](../system-design/index.md)

---

## 1. Контекст

ТЗ v1.2 §11.4 и §12.3 фиксируют `ruff + mypy` и `mypy` в CI. Проект использует Pydantic v2,
`pydantic-settings`, Typer и публичный API с `py.typed`; код ядра ещё не написан, поэтому
миграционной стоимости нет.

mypy требует отдельного плагина `pydantic.mypy` и настройки его опций. Pyrefly предоставляет
встроенную поддержку Pydantic v2 (`BaseModel`, `Field`, `ConfigDict`, `BaseSettings`, aliases,
frozen-модели, strict/lax-валидация), работает быстрее и совмещает проверку с language server.

## 2. Решение

- Основной type checker — **Pyrefly**, `preset = "strict"`, `python-version = "3.11"`.
- Конфигурация живёт в `[tool.pyrefly]` в `pyproject.toml`.
- В CI выполняется `pyrefly check`; вывод — GitHub-аннотации.
- mypy **не входит** в блокирующий CI. Его можно добавить позже как дополнительную проверку,
  если появится запрос от пользователей библиотеки или понадобится mypy-специфичная диагностика.
- `py.typed` и публичный API не зависят от выбранного чекера: библиотека остаётся совместимой
  с mypy, Pyright и Pyrefly у потребителей.

## 3. Последствия

- ТЗ v1.2 §12.3 временно расходится с реализацией в части mypy. Обновить формулировку в v1.3.
- Диагностика Pyrefly не идентична mypy; цель — не совпадение вывода, а строгая проверка проекта.
- Кастомные mypy-плагины не поддерживаются. Проекту они не нужны: плагины metadata-generator —
  это runtime entry points, а не type-checker plugins.
- Встроенная поддержка Pydantic v2 продолжает развиваться. После появления реальных моделей
  нужно проверить aliases, validators, вложенные контейнеры и `model_config`.

## 4. Альтернативы

- **mypy + `pydantic.mypy`** — зрелый стандарт, но медленнее и требует плагин и его настройки.
- **Оба чекера в CI** — выше покрытие, но дороже и даёт разные диагностики без явной выгоды
  на старте.
- **Pyright** — зрелый и быстрый, но поддержка Pydantic частичная (через `dataclass_transform`).
