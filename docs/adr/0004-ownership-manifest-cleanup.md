# ADR-0004: Ownership, manifest и cleanup

- **Статус:** принято
- **Дата:** 2026-11-11
- **Связанные документы:** [ТЗ v1.2 §10](../requirements/v1.2.md), [System Design §8](../system-design/index.md)

---

## 1. Контекст

Несколько генераторов могут писать в один `output_dir`, рядом лежат пользовательские файлы.
Без явного ownership cleanup может удалить чужой файл, а `on_conflict: skip` — молча присвоить
его генератору. Нужны безопасные правила перезаписи, удаления и восстановления после сбоя.

## 2. Решение

- Ownership определяется **per-generator manifest**:
  `output_dir/.mg/manifests/<generator-id>.json`.
- Перезаписывать и удалять можно только пути из manifest этого генератора.
- `on_conflict: overwrite | skip | error`:
  - `overwrite` — owned-файл перезаписывается; не-owned — MG041 без `--force`;
  - `skip` — owned-файл не трогается и попадает в manifest с `skipped: true` и текущим
    `sha256` файла на диске; не-owned не трогается и **не** попадает в manifest (Warning MG043);
  - `error` — любой существующий файл (owned или нет) даёт MG041; генератор не пишет.
- `--force` разрешает перезапись не-owned файла; после записи файл становится owned.
- Manifest хранит `manifest_version`, `path`, `sha256`, `skipped` и метаданные
  генератора/формата/версий.
- Cleanup удаляет только unchanged owned-файлы, которых нет в текущем результате генератора.
  Изменённый вручную файл сохраняется с Warning MG050. Записи `skipped: true` не удаляются никогда.
- Cleanup выполняется только для успешно завершившихся генераторов. Упавший генератор свой
  manifest не меняет.
- `cleanup` по умолчанию `off`; `enabled` удаляет; `prompt` в v0.3 не поддерживается:
  всегда fallback `off` + Warning MG030. Интерактивный prompt — future (v1.3).
- При `cleanup: off` stale-записи сохраняются в manifest, чтобы следующий cleanup мог их найти.
- Запись атомарная: staging внутри `output_dir`, затем `os.replace`; manifest пишется последним.
- Параллельные запуски в один `output_dir` запрещены lock-файлом `.mg/lock`.
- Пути валидируются: относительный POSIX, без `..`, NUL, backslash, reserved names; NFC;
  symlink за пределы `output_dir` — MG040; case-collision — MG042.

## 3. Последствия

- Пользовательские файлы не удаляются и не перезаписываются без `--force`.
- Manifest не коммитится; `.mg/` рекомендуется в `.gitignore`.
- Batch-транзакции нет: при аварии возможен частично обновлённый набор, manifest помогает
  обнаружить drift по sha256.
- `mg clean` удаляет unchanged owned-артефакты и оставляет изменённые.

## 4. Альтернативы

- Один общий manifest на `output_dir` — отклонено: конфликты ownership между генераторами.
- Сканировать `output_dir` и удалять «неизвестные» файлы — отклонено: опасно для пользователя.
- Хранить ownership в расширенных атрибутах файла — отклонено: не переносимо.

## 5. Известные отклонения v0.3

- `cleanup: prompt` в v0.3 всегда откатывается к `off` + MG030; tty-подтверждение
  запланировано на v1.3. ТЗ v1.2 §10.5 требует prompt только в tty — зафиксировать уточнение
  в следующей версии ТЗ.
- Код MG030 пока описан только в `docs/reference/diagnostics.md`; внести его в ТЗ §9.1
  и System Design §4.4 в v1.3.
- `mg clean` в v0.3 неинтерактивен, берёт lock и не использует `--yes`; интерактивное
  подтверждение — future.
