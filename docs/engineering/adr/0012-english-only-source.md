# ADR-0012: English-only source code, docstrings and diagnostics

- **Статус:** принято
- **Дата:** 2026-11-13
- **Связанные документы:** [ТЗ v2.2 §1, §6, §8](../requirements/v2.2.md), [ADR-0011](./0011-public-api-v2-identity.md)

---

## 1. Контекст

Проект готовится к публикации на GitHub и PyPI. Идентификаторы уже английские, но
комментарии, docstrings, CLI help и сообщения диагностик оставались на русском.
Это создаёт языковой разрыв для международных пользователей и усложняет API Reference.

Публичного релиза ещё не было, поэтому смена языка пользовательских сообщений не требует
обратной совместимости.

## 2. Решение

- Source code, comments, docstrings, CLI help и диагностические сообщения — **English-only**.
- Идентификаторы, пути, флаги CLI и коды диагностик — English/ASCII.
- Пользовательская документация может оставаться на русском; это отдельный слой.
- Docstrings — Google style, на английском.
- Публичные модули, классы и функции документируются; приватные helper-ы — только если
  логика неочевидна.
- Для контроля используется `ruff` (`D`-правила) с per-file ignores для тестов/инструментов.
- API Reference генерируется из docstrings через `mkdocstrings`.

## 3. Русские формулировки

Перед переводом сохраняется translation memory:

```text
docs/engineering/i18n/ru-messages.yaml
docs/engineering/i18n/ru-docstrings.yaml
```

Baseline commit фиксируется в `docs/engineering/i18n/README.md`.
Комментарии и исторические версии кода доступны в Git.

## 4. i18n

Полноценная локализация (gettext, locale, pluralization) **откладывается** до первого
публичного релиза. Коды диагностик стабильны, поэтому локализация может быть внешней:
UI/документация отображает `EGxxx` на нужном языке.

## 5. Последствия

- Логи, JSON-отчёт и CLI понятны международной аудитории.
- Русские сообщения не теряются: они сохранены в translation memory и Git.
- Новые строки добавляются только на английском.
- Перевод пользовательской документации — отдельное решение.
