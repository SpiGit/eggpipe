# Reference-генераторы

Готовый набор из четырёх генераторов на decorator API: SQL DDL, Pydantic v2,
TypeScript и OpenAPI 3.1. Один и тот же `ModelSlice` превращается в артефакты для
разных стеков — пример удобно копировать как основу своего плагина.

Исходник: [examples/reference-generators](https://github.com/SpiGit/eggpipe/tree/main/examples/reference-generators).

## Что генерируется

| Генератор `id` | Артефакт | Содержимое |
|----------------|----------|------------|
| `sql` | `schema.sql` | `CREATE TABLE` на сущность, `NOT NULL` для `required` |
| `pydantic` | `models.py` | Pydantic v2 `BaseModel` |
| `typescript` | `models.ts` | `export interface` на сущность |
| `openapi` | `openapi.json` | OpenAPI 3.1, `components.schemas` |

Все генераторы объявлены как `@generator(..., output_scope="model")`, возвращают
`list[Artifact]` и не пишут файлы сами — записью занимается ядро.

## Установка

```bash
pip install -e examples/reference-generators
eggpipe gen list
```

В списке появятся `sql`, `pydantic`, `typescript` и `openapi`.

## Модель

```yaml
format: entity-model
version: "1.0"
model:
  entities:
    - name: User
      fields:
        - name: id
          type: integer
          required: true
        - name: email
          type: string
          required: true
        - name: createdAt
          type: datetime
          nullable: true
```

## Подключение

```yaml
version: "1.0"
sources:
  - path: ./model.yaml
    layout: monolith
generators:
  - id: sql
    output_dir: ./out
  - id: pydantic
    output_dir: ./out
  - id: typescript
    output_dir: ./out
  - id: openapi
    output_dir: ./out
```

```bash
eggpipe generate
```

## Пример вывода

`out/schema.sql`:

```sql
-- Generated by eggpipe. Do not edit.

CREATE TABLE user (
    id INTEGER NOT NULL,
    email VARCHAR(255) NOT NULL,
    created_at TIMESTAMP
);
```

`out/models.py`:

```python
# Generated by eggpipe. Do not edit.

from __future__ import annotations
from datetime import datetime

from pydantic import BaseModel


class User(BaseModel):
    id: int
    email: str
    created_at: datetime | None = None
```

`out/models.ts`:

```typescript
// Generated by eggpipe. Do not edit.

export interface User {
  id: number;
  email: string;
  createdAt?: string | null;
}
```

`out/openapi.json` (фрагмент):

```json
{
  "components": {
    "schemas": {
      "User": {
        "properties": {
          "createdAt": {"format": "date-time", "type": ["string", "null"]},
          "email": {"type": "string"},
          "id": {"type": "integer"}
        },
        "required": ["id", "email"],
        "type": "object"
      }
    }
  },
  "openapi": "3.1.0"
}
```

## Маппинг типов

| Тип поля | SQL | Pydantic | TypeScript | OpenAPI |
|----------|-----|----------|------------|---------|
| `string` | `VARCHAR(255)` | `str` | `string` | `string` |
| `text` | `TEXT` | `str` | `string` | `string` |
| `integer` | `INTEGER` | `int` | `number` | `integer` |
| `bigint` | `BIGINT` | `int` | `number` | `integer` (`int64`) |
| `float` | `DOUBLE PRECISION` | `float` | `number` | `number` (`double`) |
| `boolean` | `BOOLEAN` | `bool` | `boolean` | `boolean` |
| `date` | `DATE` | `date` | `string` | `string` (`date`) |
| `datetime` | `TIMESTAMP` | `datetime` | `string` | `string` (`date-time`) |
| `uuid` | `UUID` | `str` | `string` | `string` (`uuid`) |
| `json` | `JSONB` | `dict[str, Any]` | `Record<string, unknown>` | `object` |
| enum, неизвестный тип | `VARCHAR(255)` | `str` | `string` | `string` |

Custom types разворачиваются до базового примитива. Имена: SQL и Pydantic —
`snake_case`, TypeScript и OpenAPI — `camelCase` для полей и `PascalCase` для
сущностей.

`required` и `nullable` независимы: `NOT NULL` ставится только для `required`,
необязательное поле в Pydantic получает `None` по умолчанию, в TypeScript — `?`,
nullable-тип в OpenAPI 3.1 становится `["string", "null"]`.

## Детерминизм

Сущности сортируются по имени, поля сохраняют порядок объявления, JSON пишется с
`sort_keys=True`, каждый артефакт заканчивается переводом строки. Поэтому вывод
подходит для `eggpipe generate --check` в CI.

## Ограничения

- Нет первичных и внешних ключей, индексов и метаданных конкретной СУБД.
- Значения `default` не выводятся, enum-поля маппятся в строку.
- Идентификаторы `sql`, `pydantic`, `typescript`, `openapi` общие: в приложении с
  собственными генераторами возможен конфликт имён.

## Тесты

```bash
uv run pytest examples/reference-generators/tests -q
```

Contract-тесты проверяют `validate_generator_contract`, имена артефактов, базовое
содержимое и детерминизм двух прогонов.
