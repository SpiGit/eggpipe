# ADR-0020: Кэш разбора документов (L2)

- **Статус:** принято
- **Дата:** 2026-11-23
- **Связанные документы:** [ТЗ v2.5 §10.7](../requirements/v2.5.md), [ADR-0017](./0017-incremental-generation.md), [ADR-0018](./0018-per-entity-generation.md), [System Design §8.6, §9.3](../system-design/index.md), [Roadmap 0.5.0](../roadmap.md), [Spike L2/L3](../spikes/2026-11-23-l2-l3-cache.md)

---

## 1. Контекст

Инкрементальная генерация (ADR-0017, L1) пропускает прогон целиком, только если не
изменился входной fingerprint и все артефакты на месте. При любом изменении одного
файла выполняется полный путь: discovery → fingerprint → parse + composition →
validation → generate → write.

Замеры ([spike](../spikes/2026-11-23-l2-l3-cache.md)) показали:

- TPC-H (8 документов): cache-hit всё равно стоит 67 мс, из них ~63 мс — повторный
  разбор YAML в discovery и fingerprint; изменён один файл — 123 мс;
- синтетика N = 120: cache-hit 294 мс, изменён один файл 457 мс — стоимость линейна
  по N и почти не зависит от факта изменения;
- каждый документ разбирается 2 раза за прогон (discovery и fingerprint), а при
  изменении — 3 раза (ещё `Parser.parse_document`);
- кэш результата композиции (L3) даёт 2–4 % прогона и не переиспользуется при
  изменении документа — его откладываем.

Roadmap 0.5.0 п. 2 требует, чтобы повторный запуск не парсил неизменённые файлы.
Нужен кэш уровня документа (L2), совместимый с opt-in `--incremental` и не меняющий
контракт CLI, отчёта и плагинов.

## 2. Решение

Вводится **L2 — персистентный content-addressed кэш разобранных документов**.
Он работает только при включённом `--incremental` и наследует все условия отключения
ADR-0017; по умолчанию поведение не меняется.

Инварианты:

- **Единица кэша — документ.** Ключ — SHA-256 байтов документа; путь, mtime и размер
  не участвуют в ключе.
- **Кэшируется только успешный разбор.** Битый YAML, неизвестный формат, ошибка
  валидации не попадают в кэш и воспроизводятся заново с теми же `EGxxx`.
- **Кэш — внутреннее состояние, а не артефакт.** Он лежит в `.eggpipe/cache/`, не
  входит в manifest, не участвует в ownership/cleanup и не может создаваться плагином.
- **Кэш недоверенный.** Любая ошибка чтения, версии или валидации записи — промах
  и полный путь; кэш никогда не ломает прогон и не маскирует диагностики.
- **Path-free payload.** `path`, `Entity.source`, `Entity.format`/`format_version`,
  `FieldDef.source` в кэше не хранятся и восстанавливаются при загрузке.
- **Контракты не меняются.** Новых флагов, полей отчёта, `EGxxx` и изменений
  публичного API нет: интеграция выполняется внутренним наследником `Parser`
  (`engine/parser_cache.py`), публичная сигнатура `Parser.parse_document` прежняя.
  Уточняется уже существующее требование ADR-0017: `parse` детерминирован, не
  зависит от пути документа и объявляет все внешние входы через `input_paths`; это
  будет явно записано в `docs/user/plugins.md`. Формат, который не может это
  гарантировать, объявляет `input_paths=None` и работает без L1/L2.

## 3. Алгоритм (design note)

### 3.1 Ключ и валидность

Запись кэша считается валидной, если одновременно:

1. `cache_version` и `eggpipe_version` совпадают с текущими;
2. `format`, `format_version`, `__version__` и `api_version` формата совпадают;
3. хэши файлов input-closure, объявленных `FormatPlugin.input_paths`, совпадают;
4. payload валидируется по внутренней схеме `core/cache.py` — она повторяет поля
   `ModelDocument` без `path` и path-зависимых полей; затем ядро достраивает
   `path`/`source`/`format*`. Публичная `ModelDocument` требует `path` и для payload
   напрямую не используется.

Fingerprint L1 по-прежнему считается по фактическим байтам: L2 ускоряет его сбор
(imports берутся из меты), но не заменяет проверку артефактов.

Форматы с `input_paths=None` отключают incremental целиком (ADR-0017) — вместе с ним
и L2. Разбор формата обязан быть детерминированным и не зависеть от пути документа:
path-зависимые поля заполняет ядро. Если формат не может это гарантировать, он
объявляет `input_paths=None` и остаётся без L1/L2.

### 3.2 Состояние

```text
.eggpipe/
  manifest.json          # без изменений (ADR-0009, ADR-0017)
  lock                   # без изменений (ADR-0017, §10.4)
  cache/
    meta.json            # cache_version, eggpipe_version, entries
    docs/<sha256>.json   # payload без path-полей
```

`meta.json` перезаписывается целиком на каждый incremental-прогон, который пишет
кэш:

```json
{
  "cache_version": 1,
  "eggpipe_version": "0.4.0",
  "entries": {
    "<sha256 hex>": {
      "format": "entity-model",
      "format_version": "1.0",
      "format_plugin_version": "0.0.0",
      "format_api_version": "1",
      "inputs": {"model/shared/base.yaml": "<sha256 hex>"}
    }
  }
}
```

`inputs` — запись на документ (`entries[<sha256>]`): пути из `input_paths`
(`base_path`-относительные, например `../shared/base.yaml`) переводятся ядром в
пути относительно каталога конфига (`model/shared/base.yaml`).

`docs/<sha256>.json` пишется только для новых документов; при записи удаляются файлы,
на которые не ссылается `meta.json` (prune до текущего набора). Абсолютные пути и
пути, выходящие за project root, считаются повреждением кэша; для source-документов
такие пути и так отключают incremental (ADR-0017).

### 3.3 Поток

1. **Discovery.** Для каждого кандидата ядро читает байты, считает digest и смотрит
   мету. Валидная запись даёт формат без полного `load_yaml`; промах — текущая
   проверка `_is_model_document`, и документ пойдёт в разбор.
2. **Fingerprint.** Для source-документов и замыкания используются уже прочитанные
   байты; imports берутся из меты, closure проверяется по хэшам. YAML повторно не
   разбирается.
3. **Parse.** Внутренний наследник `Parser` сначала спрашивает кэш: валидная запись
   загружается из `docs/<sha256>.json` и получает path-поля; иначе документ
   разбирается базовым `Parser` и помечается для записи. `Engine` создаёт этот
   наследник только при включённом incremental.
4. **Write.** Новые записи пишутся в конце `generate` под существующим
   `.eggpipe/lock`; замена `meta.json` и файлов payload атомарная (tmp + `os.replace`).

`--plan` использует кэш только на чтение: писать состояние без lock нельзя.
Изменённый документ даёт один промах; остальные N−1 берутся из кэша.

### 3.4 Path-зависимые поля

Кэшируется `ModelDocument` без `path`, `Entity.source`, `Entity.format`,
`Entity.format_version`, `FieldDef.source`. При загрузке ядро заполняет их тем же
способом, что и `Parser.parse_document`. Одинаковое содержимое в двух путях даёт
одну запись и два разных восстановленных документа — это ожидаемо.

### 3.5 Ошибки и повреждение

- Ошибка чтения/JSON/валидации любой части кэша — debug-лог, промах, полный разбор;
  повреждённая запись удаляется при следующей записи.
- Ошибка записи кэша (диск, права) — debug-лог, прогон успешен; кэш просто не
  обновится.
- Новый `cache_version` от другой версии Eggpipe читается как промах; старые версии
  Eggpipe не видят `.eggpipe/cache/` и работают как раньше.

### 3.6 Конкурентность и границы

- Чтение кэша lock не требует.
- Запись — только под `.eggpipe/lock`, который уже берётся `generate`; параллельные
  процессы сериализуются на lock.
- Watch создаёт новый `Engine` на прогон, поэтому кэш должен быть персистентным, а не
  привязанным к экземпляру `Engine`.
- Кэш не чистится `eggpipe clean`: `--clean` отключает incremental (ADR-0017), а
  запускаемый `generate` сам выполняет prune неактуальных записей.

## 4. Инвалидация

| Что изменилось | Результат |
|----------------|-----------|
| Содержимое документа | Новый digest — промах, старый payload удаляется prune’ом |
| Файл переименован/перемещён, содержимое то же | Digest тот же — попадание; path-поля восстанавливаются |
| `version`/`format` в документе | Меняется содержимое — промах |
| `FormatPlugin.__version__`/`api_version` формата | Валидность записи не проходит — полный разбор |
| Версия Eggpipe или `cache_version` | Кэш не читается — промах |
| Файл из `input_paths`-closure | Хэш в `inputs` не совпал — промах |
| Документ не разбирается (EG000/EG008/EG028) | В кэш не попадает; ошибка воспроизводится |
| `--entity`, `--check`, `--force`, `--clean`, `--strict`, `stale_dates`, outside paths | L2 не используется вместе с incremental |
| Повреждён `meta.json`/payload | Промах и полный разбор; прогон успешен |

## 5. Последствия

- Ожидаемый эффект (оценка spike): TPC-H cache-hit 67 → 3–5 мс, изменён 1 из 8 —
  123 → ~30 мс; N = 120 — 294 → ~3 мс и 457 → ~34 мс.
- Поведение по умолчанию, CLI, отчёт, плагинные контракты не меняются. `timings`
  остаются прежними: `parse_ms` отражает загрузку из кэша, `fingerprint_ms` — реальный
  сбор fingerprint.
- Появляется новое внутреннее состояние `.eggpipe/cache/`; его формат внутренний и
  версионируется полем `cache_version`. ТЗ v2.4 новую версию не требует: публичный
  контракт не меняется (аналогично ADR-0019).
- Размер: `meta.json` — O(N); payload ≈ 1.3× исходников (TPC-H ~13 КБ, 1000
  документов ~1.3 МБ).
- Безопасность: кэш валидируется как недоверенный ввод; payload не содержит путей,
  `inputs` не может выходить за project root.
- Ограничение ADR-0017 сохраняется: изменение кода плагина без bump версии не
  инвалидирует кэш; плагин с внешними входами обязан объявлять их через `input_paths`.
- System Design §8.6/§9.3 синхронизируется в PR реализации: зарезервированный
  `CacheStrategy` заменяется контрактом кэша документов.

## 6. Альтернативы

1. **Только микрооптимизации (вариант A из spike).** Discovery без полного YAML и
   переиспользование raw-dict в рамках одного запуска дают ~2×, но не убирают
   повторный разбор в fingerprint и не помогают однократному CLI-запуску. Отклонено
   как самостоятельное решение; остаётся допустимой подготовкой.
2. **Кэш результата композиции (L3).** Экономит 2–4 % до L2 и не переиспользуется
   при изменении документа. Отложено; возможный следующий шаг — инкрементальное
   слияние, а не кэш готового результата.
3. **Только in-memory кэш.** Не помогает CLI-запуску; watch и так создаёт новый
   `Engine`. Отклонено.
4. **Инвалидация по mtime/размеру.** Гонки, грубый mtime, ложные промахи при
   `touch`; не ловит изменения при сохранении mtime. Отклонено в пользу SHA-256.
5. **Хранить кэш в `manifest.json`.** Manifest описывает ownership артефактов и
   валидируется схемой; payload документов раздувает его и связывает несвязанные
   контракты. Отклонено в пользу отдельного `.eggpipe/cache/`.
6. **SQLite.** Лишняя зависимость ради состояния, которое читается целиком; JSON
   достаточно. Отклонено.

## 7. Файлы реализации и non-goals

PR реализации (отдельно от этого ADR):

| Файл | Изменение |
|------|-----------|
| `src/eggpipe/core/cache.py` | протокол кэша и path-free payload |
| `src/eggpipe/engine/document_cache.py` | чтение/запись `.eggpipe/cache/`, prune, валидация |
| `src/eggpipe/core/discovery.py` | формат из меты без полного `load_yaml` |
| `src/eggpipe/engine/parser_cache.py` | внутренний наследник `Parser` с загрузкой из кэша |
| `src/eggpipe/engine/engine.py` | wiring, fingerprint из меты, запись под lock |
| `tests/test_document_cache.py`, `tests/test_incremental.py` | матрица §8 |
| `engineering/system-design/index.md` §8.6/§9.3 | контракт L2 |
| `engineering/benchmarks.md` | замеры до/после |
| `docs/user/plugins.md` | требование path-независимости `parse` |

Non-goals:

- L3 и инкрементальное слияние композиции;
- кэш на уровне entity и per-entity watch;
- новые CLI/env-флаги, поля отчёта и `EGxxx` (метрики кэша — вместе с ТЗ v2.5);
- вытеснение по размеру сверх prune до текущего набора;
- кэширование неуспешного разбора и диагностик.

## 8. Тестовая матрица

| Сценарий | Ожидание |
|----------|----------|
| Холодный прогон → повторный no-op | Первый пишет кэш; второй: `parse_ms = 0`, YAML не разбирается, отчёт соответствует no-op incremental без L2 (ADR-0017 §6: `skipped`, нулевые timings, пустая сводка `formats`) |
| Изменён 1 из N | Разбирается один документ, остальные из кэша; артефакты те же |
| Переименование без изменения | Попадание, path-поля указывают на новый путь |
| Одинаковое содержимое в двух путях | Одна запись, два корректных документа при загрузке |
| Повреждённый `meta.json`/payload | Промах, полный разбор, прогон успешен |
| Изменён `plugin_version`/`cache_version` | Промах |
| Изменён файл из `input_paths` | Промах |
| Документ с ошибкой (EG000/EG008/EG028) | Не кэшируется, код и путь те же |
| `--entity`, `--check`, `--force`, `--clean`, `--strict` | Кэш не используется |
| `--plan` | Кэш читается, новые записи не пишутся |
| Формат с `input_paths=None` | Incremental и L2 отключены |
| Повторный `generate` после `--plan` | Кэш пополняется только в `generate` |

## 9. Открытые вопросы

- Поля метрик кэша (hits/misses) — вместе с пунктом 3 roadmap и ТЗ v2.5, не в PR L2.
- Нужен ли предел на число записей сверх prune, если пользователь часто меняет ветки с
  разным содержимым; решается по замерам, по умолчанию — только prune.
- Публично ли документировать формат `.eggpipe/cache/`: сейчас — внутренний, версия
  в `cache_version`; решение о публикации — вместе с ТЗ v2.5.
