# ADR-0015: Ветвление и релизная политика

- **Статус:** принято
- **Дата:** 2026-11-16
- **Связанные документы:** [ADR-0014](./0014-beta-status-and-compatibility.md), [Релиз](../release.md), [Roadmap](../roadmap.md)

---

## 1. Контекст

Проект небольшой, развивается одним мейнтейнером, но уже опубликован на PyPI и GitHub.
`main` защищён, изменения идут через pull request, релизы запускаются тегами.

Нужно определить, нужна ли постоянная ветка `develop`, где ведётся разработка, а `main`
используется только для релизов.

## 2. Решение

Используется **trunk-based development** с короткоживущими ветками.

- `main` — единственная постоянная ветка; она всегда должна быть зелёной и потенциально
  релизной.
- Работа ведётся в ветках `feat/*`, `fix/*`, `docs/*`, `chore/*`.
- Merge в `main` — только через pull request и зелёный `ci-success`.
- Релиз — тег `vX.Y.Z` на `main`; тег запускает release workflow.
- Постоянная ветка `develop` не вводится.
- Для стабилизации или поддержки старой линии может создаваться временная
  `release/X.Y`.
- Для больших breaking-изменений допускается временная ветка `next`, которая
  сливается в `main` до релиза.

## 3. Ветки

| Ветка | Назначение | Время жизни |
|-------|------------|-------------|
| `main` | Интеграция и релизная линия | Постоянная |
| `feat/*` | Новая функциональность | До merge |
| `fix/*` | Исправление | До merge |
| `docs/*` | Документация | До merge |
| `chore/*` | Инфраструктура, CI, зависимости | До merge |
| `release/X.Y` | Стабилизация и патчи линии | Пока нужна линия |
| `next` | Крупный breaking-рефакторинг | До merge |

## 4. Релиз

1. Изменения попадают в `main` через PR.
2. Перед релизом — PR с версией, `CHANGELOG.md` и обновлением документации.
3. После merge ставится аннотированный тег `vX.Y.Z`.
4. Тег запускает `release.yml`: сборка, GitHub Release, публикация на PyPI.
5. Теги не перемещаются и не удаляются после публикации.
6. Предрелизы — теги `vX.Y.ZrcN`; GitHub Release помечается как prerelease,
   PyPI получает prerelease-версию.

## 5. Патчи и hotfix

- Патч выпускается из `main`, если релизная линия совпадает с текущей.
- Для старой линии создаётся `release/X.Y` от тега, патч идёт через PR в эту ветку,
  затем тег `vX.Y.Z`.
- Исправление из `release/X.Y` переносится в `main`, чтобы не терять его.

## 6. Защита

- `main`: PR обязателен, `ci-success` обязателен, force-push и удаление запрещены.
- Теги `v*`: создание и изменение ограничены мейнтейнером.
- Environment `pypi`: рекомендуется включить required reviewers, чтобы публикация
  не происходила без подтверждения.

## 7. Когда пересмотреть решение

Ввести постоянную `develop` имеет смысл, если:

- появится несколько активных разработчиков;
- понадобится одновременно поддерживать старую линию и разрабатывать новую;
- появятся длительные фичи, которые нельзя мержить в `main` часто.

Такое изменение оформляется новым ADR, а не правкой этого.

## 8. Последствия

- Меньше merge-конфликтов и расхождений между ветками.
- Релиз всегда можно воспроизвести по тегу.
- `main` может содержать изменения, ещё не попавшие в релиз; это нормально для
  trunk-based.
- Для старых линий используется `release/X.Y`, а не постоянный `develop`.
