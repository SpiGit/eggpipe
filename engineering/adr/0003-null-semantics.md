# ADR-0003: Null-семантика, `UNSET` и default

- **Статус:** принято
- **Дата:** 2026-11-11
- **Связанные документы:** [ТЗ v1.2 §3.6, §3.7](../requirements/v1.2.md), [System Design §3.1](../system-design/index.md)

---

## 1. Контекст

У поля есть три независимых свойства: `required`, `nullable` и `default`. Если представлять
отсутствие `default` и `default: null` одним значением `None`, невозможно отличить «значение
не задано» от «явно задан null». Это ломает null-матрицу и сериализацию модели.

## 2. Решение

- Внутри ядра используется sentinel `UNSET`. Отсутствие ключа `default` в YAML — это `UNSET`,
  а `default: null` — явное значение `None`.
- `required` — наличие значения **после применения default**. `nullable` — допустимость `null`
  в предоставленном значении. Оба по умолчанию `false`.
- Null-матрица — все 12 комбинаций `required × nullable × default` из ТЗ §3.6.
- `nullable=false` + `default=null` — **Error MG010** (независимо от `required`).
- `required=true` + `nullable=true` — **Warning MG011** (в v1 нет PATCH-семантики).
- `default` проверяется против итогового типа, enum и constraints: MG016/MG017.
- Pydantic отвечает только за структуру. Null-матрица, default и constraints проверяются
  в `validator.py`, чтобы иметь код, уровень и локацию.
- Constraints поля и `CustomType` сливаются по атрибутам. Атрибут, явно заданный на поле,
  переопределяет тип; явный `null` сбрасывает constraint. Это слияние не применяется
  к `entity.extends`: при наследовании поле child заменяет родительское целиком (ADR-0001).
- При сериализации `FieldDef` с `UNSET` ключ `default` **опускается**, а не превращается в `null`.

## 3. Последствия

- `FieldDef.default is UNSET` — единственный способ отличить отсутствие default.
- `UNSET`, `FormatPlugin`, `EntityModelFormat` и `PRIMITIVE_TYPES` входят в стабильный
  публичный API; их включение в ТЗ §6.2 фиксируется в v1.3 (см. ADR-0005).
- YAML `default: null` допустим только при `nullable: true`.
- JSON Schema и `model_dump` не содержат `default`, если он не задан.
- Формат-плагин может добавить свои правила, но не может отменить MG010.

## 4. Альтернативы

- Использовать `None` как единственный sentinel — отклонено: теряется различие «не задан/null».
- Хранить отдельный флаг `default_set` — отклонено: дублирует состояние и легче рассинхронизировать.
- Перенести null-матрицу в Pydantic — отклонено: нужны структурированные диагностики и уровни.
